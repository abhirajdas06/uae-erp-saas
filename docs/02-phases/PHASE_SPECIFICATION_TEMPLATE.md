# PNN — Phase Specification Template

| Property | Value |
|---|---|
| Document ID | PNN-SPEC-001 |
| Status | TEMPLATE |
| Implementation Authorization | Not granted by this document |

## 1. Objective

State the business and technical outcome.

## 2. Governing sources

Link product requirements, ADRs, architecture, module specifications, quality standards, prior-phase evidence, decisions, and risks.

## 3. Entry gate

List dependencies, approvals, required decisions, environment/evidence prerequisites, and current state.

## 4. Bounded scope and non-goals

Identify included modules/capabilities and exclusions.

## 5. Task packages and dependencies

Every task requires a stable ID, objective, source requirements, scope, permissions, acceptance criteria, tests, evidence, reviewers, and rollback/recovery expectations.

## 6. Deliverables

List code, data, migration, test, security, documentation, and operational deliverables.

## 7. Acceptance criteria

Use stable phase-level identifiers and measurable evidence.

## 8. Security, tenant isolation, and data integrity

Define the phase-specific controls and no-waiver gates.

## 9. Migration and operational requirements

Define clean install, upgrade, rollback/forward-fix, deployment, observability, backup/recovery, and support requirements.

## 10. Test and evidence plan

Map criteria to tests, reviewers, evidence IDs, artifact retention, and status.

## 11. Exit gate

Define mandatory criteria, prohibited exceptions, defect thresholds, independent reviews, Product Owner approval, and next-phase authorization boundary.

## 12. Pending approvals

For each approval state the ID, approver, decision, evidence, recommendation, consequence, exact approval statement, and blocked scope.
